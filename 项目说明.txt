破妄 · 项目说明
=================================
基于微调大模型的对互联网社区的评论情感分析软件
=================================

一、项目概述
  破妄是一款对B站社区评论进行六分类情感分析的软件。
  六分类：赞美 / 贬低 / 水军 / 无意义 / 社区对骂 / 中立。
  核心：人工精标"锚定集"(少量)作为分类依赖模板 + 网络用语RAG知识库 + 大模型(智谱glm-4-flash/微调后模型) + LangChain Agent问答。
  展示：包豪斯风格单页前端，含饭圈(演艺圈)/二游(游戏圈)双社区对比、情感洞察看板、评论态度关系图谱与页内AI问答。

二、目录结构
  comment_crawler.py       B站评论爬虫(多策略分层采样+反爬+断点续采)
  sentiment_analyze.py     锚定集检索式分类引擎 + RAG注入 + 聚合统计
  rag_knowledge.py         网络用语RAG知识库(含"砌墙"等梗)
  agent_chat.py            LangChain洞察Agent(查统计/趋势/热词/对比/网络用语)
  export_finetune.py       微调数据集导出(智谱JSONL格式)
  app.py                   Flask后端(页面+数据/标注/审查/分析/问答API)
  project_main.py          fire CLI 主入口(crawl/analyze/export/serve/stats)
  benchmark_methods.py     表4对照实验(词典基线/零样本/检索式RAG/微调 对锚定集评测)
  front/                   包豪斯前端(landing/comments/label，看板与问答已并入首页)
  data/
    crawled/               爬取的评论JSON(两视频)
    analysis/              分析结果JSON(含逐条分类+聚合统计)
    labels/anchors.json    锚定集(人工精标)
    finetune/              微调数据集
    slang_dict.json        网络用语词典(混合基础词典)
    rag_knowledge.json     RAG知识库(词条+含义+示例)
    config.json            API配置(APIKey/模型/视频，含饭圈/二游标签)
    cookie.txt             登录Cookie(buvid3+SESSDATA，敏感勿提交)
  requirements.txt         依赖清单
  启动破妄.bat            一键启动脚本
  分析与选型报告.md        技术选型+方法论(论文素材)
  展示-破妄.txt            对外展示文案

三、运行环境
  Python 3.12 (需含 requests, flask, flask-cors, langchain>=1.0, langchain-openai, pydantic>=2, fire)
  安装：pip install -r requirements.txt

四、运行步骤
  1) 配置 API Key：编辑 data/config.json 的 api_key 字段
        (智谱GLM，免费模型 glm-4-flash)
  2) 启动：双击"启动破妄.bat" 或 命令行 python app.py
        → 浏览器打开 http://localhost:5000
  3) 标注锚定集：进入"标注"页(/label)，切换视频(明日方舟PV/TF家族音乐会)，
        逐条点击 赞美/贬低/水军/无意义/社区对骂/中立 按钮标注(快捷键1-6)，
        每视频至少50条即可触发分析(建议目标100条)，可点"追加标注"随时扩充。
  4) 触发分析：两视频各完成50条后，点"开始调用大模型分析"，后台分析全量评论。
  5) 二次审查：分析完成后切到"二次审查"标签，对模型结果确认/修正(修正进锚定集)。
  6) 首页洞察：在首页"情感洞察看板"区域切换单视频或"双社区对比"，查看
        六分类占比/时间趋势/高频网络用语/代表性评论。
  7) 关系图谱与问答：继续向下查看全屏评论态度关系图谱，图谱下方即为AI问答区。
  8) CLI：python project_main.py --mode stats / crawl / analyze / export / dedup / serve
        dedup 模式：对语料做近重复清洗(bigram-Jaccard>=0.7，保留簇内高赞代表)

五、微调大模型(阶段二)
  1) 确保已标注锚定集并完成一次分析
  2) 运行：python project_main.py --mode export
        → 生成 data/finetune/trainset.jsonl (智谱微调格式)
  3) 登录智谱开放平台 https://open.bigmodel.cn
        → "模型微调" → 新建微调任务 → 上传 trainset.jsonl
        → 选择基础模型(如 glm-4-flash) → 提交训练(按平台计费,少量)
  4) 训练完成获得"微调模型ID"
  5) 在 data/config.json 的 fine_tuned_model 填入微调模型ID
  6) 重新触发分析，即用微调后模型；对比前后结果看"微调增益"
  7) 论文表4指标：python benchmark_methods.py
        对锚定集自动评测 词典基线/零样本LLM/检索式+RAG/微调 四种模式，
        产出 Accuracy/Macro-F1/水军Recall 与混淆矩阵，
        结果写入 data/analysis/benchmark_report.json(含表4可直接粘贴的Markdown行)
        (词典基线 --methods dict 不消耗API；--selftest=true 可先自检分类器)

六、注意事项
  * data/cookie.txt 和 data/config.json 含敏感信息，勿提交/勿外发，勿写入文档
    （完整脱敏与公网部署清单见第八节，git提交前必读）。
  * 爬虫已做限速与风控规避；请勿高频调用，避免B站封禁登录Cookie。
  * 若模型报429限流，系统自动降级备用模型(glm-4-flash-250414)。
  * 分析全量(4267/2932条)耗时较长，可断点续跑(已分析的跳过)。
  * B站已限制主评论翻页(每视频仅最新/热度各3条可达)，增量抓取以子评论层为主
        (按子评论数取前80个主楼、每楼最多5页)；反复运行 crawl 仍可持续增量。
  * 高频热词数据：未分析时由词典+RAG词条对语料做命中频次统计(带缓存)，
        分析完成后自动切换为模型标注热词(slang_tags)。
  * 网络用语知识库 data/rag_knowledge.json 可不断补充新梗。

八、脱敏与开源/公网部署清单(报名传智杯前必读)
  1) 永不入库、永不外发的文件(已列入 .gitignore)：
     - data/config.json   真实智谱API Key
     - data/cookie.txt    B站登录态(buvid3+SESSDATA)
     首次运行：复制 data/config.example.json 为 data/config.json 再填Key；
     cookie.txt 自行放置(勿向任何人提供)。
  2) 代码与文档：任何源码/README/论文/截图/演示视频不得出现Key与Cookie明文；
     若曾在代码里硬编码过Key，立即到智谱平台作废重发，并重建git历史
     (或废弃旧仓库重开)，防止历史提交里残留。
  3) 公网部署(大模型赛项要求可公开访问的在线演示地址)：
     - API Key 改用环境变量注入，服务器上不落盘、不进镜像；
     - 反向代理与访问日志不要记录含Cookie的请求头；
     - 演示环境关闭或严格限速爬虫入口，避免公网触发B站风控连累账号。
  4) 数据合规：crawled评论为平台公开数据；论文与演示中用户昵称/UID
     展示时打码；不向第三方二次分发原始语料。
  5) git push 前自查：git grep -n "SESSDATA" 应无命中，
     并人工检查涉及 config 的diff确认无真实Key；仓库必须保留
     data/config.example.json 模板以便评委复现。
