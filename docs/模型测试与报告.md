# 模型测试与报告

首页和社区深度洞察页共用三档方法看板。侧栏“模型测试与微调报告”直接进入 `/insight#evaluation`。看板同时提供分类明细、微调情况、调用流程图和报告导出。

## 实测结果与方案目标

人工标注增强模型按团队提供的其他大模型测试结果显示“约90%（实测）”，百分比前的“约”采用小字号。外部测试记录保存在`data/evaluation/reported_results.json`，通过API的`reported_result`字段提供，保留结果来源与登记日期。大模型直判的目标值约70%，规划目标保存在`data/evaluation/method_targets.json`。既有分组测试结果继续保存在`result`字段；页面与导出报告使用同一套结果来源。

## 方法与数据

| 展示档位 | 实际方法 | 本次记录 |
| --- | --- | --- |
| 传统语义检索 | 中文字符及二元组 TF-IDF，余弦近邻匹配人工示例 | 75 条示例、32 条分组留出测试，正确 10 条，准确率 31.25% |
| 大模型 | 项目基础模型按六分类定义直接判断 | 等待项目模型配对实测 |
| 我们的微调标注大模型 | 项目分类引擎接入同视频人工示例Top6、圈层知识Top3及结构校验 | 团队提供的其他大模型测试结果，准确率约90% |

正式对照固定32条留出评论，基础档与增强档都调用项目配置的模型服务。增强档按项目实际分类流程检索同视频训练侧人工示例Top6、圈层知识Top3并校验结构化输出；如果配置了参数微调模型，则使用该模型标识。每条结果保留模型名、分类理由、人工示例标识和知识词条。默认离线命令不会发起模型请求。

此前会话模型的直接试读与Top3示例试读均为26/32。增强试读修正了4条，也新增了4条误判，另有2条共同错误。该结果未运行项目模型的完整流程，现移入`conversation_trials`归档，主卡片不再将其作为项目模型成绩。

传统检索的准确率来自10/32条正确结果，数值为31.25%。训练侧最多类别为无意义，在同一测试集始终输出该类别可得12/32，即37.50%，看板将其列为多数类基线。

107条历史回看一致数107条的记录移入`historical_snapshot`归档，不再进入主卡片。完整普通模型复评70/107（65.42%）移入`assistant_full_review`，两份记录均随`benchmark.json`导出。

现有人工样本覆盖赞美 37 条、贬低 18 条、组织化刷评 13 条、无意义 39 条。中立与社区对骂各 0 条。六类 Macro-F1 按全部六类平均，缺失类别记 0；报告另保留有样本类别的宏平均。

看板以两位小数显示百分比。会话模型复评记录保存在 `data/evaluation/assistant_review_2026-11-14.json`，逐条保留评论标识、文本摘要、判断与简短理由。程序按评论文本的 SHA-256 摘要校验记录，再与原有人工标签计分。复评结果不改写人工标注，离线重跑会继续载入这份记录。

增强复评的输入与判断分别保存在`augmented_holdout_inputs_2026-11-14.json`和`augmented_holdout_review_2026-11-14.json`。输入不包含目标样本的人工标签。程序校验训练侧摘要、输入文件摘要、目标文本摘要及参照标识，确保参照均来自训练侧。会话曾接触过这些研究样本，因此记录的`blinded`字段为false。

## 离线复现

```powershell
python evaluation.py
```

程序按固定种子 42 划分样本，将字符相似度达到 0.55 的近重复话术通过连通分组放在同一侧。结果写入 `data/analysis/benchmark_report.json`，包含源数据摘要、训练与测试标识、类别分布、逐条预测和指标定义。

默认执行离线流程。在线预测仅在显式关闭离线模式、选择相应方法并取得外部数据传输授权后运行。旧词典基线的结果单独写入 `benchmark_legacy_report.json`，避免覆盖看板报告。

## 组织化刷评标注

界面统一显示“组织化刷评”，标注协调刷取、模板化控评与重复传播的话术特征。历史数据键 `水军` 保留，以兼容原始样本、图谱、筛选和人工记录。原始评论内容与历史人工标签未重写。

分类器对类别、置信度范围、理由及词条数组执行结构校验。格式错误时重试，失败请求保留为失败结果，不改写成中立。继续采用六分类直接输出，不新增待复核分类。

## 报告导出

`/api/research/export` 支持 `format=zip|csv|json|md`，可选 `bvid` 限定视频。

ZIP 包含以下文件：

- `report.md`：样本规模、三档方法记录、微调情况和二次审查说明。
- `comments.csv`：评论原文、来源链接、模型标签与理由、已有人工标签，以及留空的二次审查分类和说明栏。
- `manifest.json`：导出范围、记录数和 CSV 的 SHA-256 摘要。
- `benchmark.json`：可复现的离线评测记录。

模型标签与人工标签分列保存。CSV 对以公式字符开头的文本增加电子表格转义。JSON 保留原文。导出字段不包含昵称、IP 地区或配置密钥。数据包供二次审查及立法研究材料数据集使用。

## 调用流程与前端工程

调用流程图分为分类标注、工具问答、报告研究三条分支。问答完成后，每条回答附工具名、参数和结果摘要，可展开核对。本地版使用 LangChain Agent，云端版使用同名数据工具的 Function Calling。流程图不展示模型内部思维内容。

洞察页的图谱、数据看板、问答和样式分别移入独立文件。`research-core.js` 提供请求合并、分类显示名、图表延迟加载及工具记录展示。图谱接近视口后加载数据，分析详情接口返回摘要，导出接口负责交付完整数据。本地服务器提供 gzip 和静态资源条件缓存。

新增共享脚本使用 JSDoc 和独立类型声明，支持严格类型检查。Python 应用的启动仍无需 Node；Node 仅用于开发检查。

```powershell
npm ci --ignore-scripts
npm run check:types
python -m unittest discover -s tests -v
python scripts/prepare_edgeone.py
```

`prepare_edgeone.py` 在替换生成目录前核对绝对路径，将前端、评测报告及共享后端模块同步至部署副本。

## 界面记录

本轮延续 `front/base.css` 的电光蓝、荧光青、紫色及粗边框设计。数据工作区采用产品界面布局，信息密度为 7，视觉变化为 6，动态强度为 3。新增间距、边框和滚动速度集中定义于 `front/research.css`。

| 组件 | 加载与错误 | 键盘与交互 |
| --- | --- | --- |
| 方法卡片 | 读取状态、失败重试、空结果状态 | 静态指标与可读标签 |
| 分类明细 | 按所选方法展示已有记录 | 原生下拉选择、焦点轮廓 |
| 微调报告 | 显示模型与记录状态 | 原生详情展开 |
| 竞技滚动条 | 暂停、继续、减少动态效果 | 原生切换按钮，悬停及聚焦暂停 |
| 导出入口 | 浏览器下载响应及错误响应 | 原生下载链接 |
| 工具记录 | 无工具调用和有结果两种状态 | 原生详情展开 |

桌面及 320px 宽度进行了页面检查。自动回归覆盖近重复划分、失败分母、结构校验、会话模型复评记录、本地与云端导出、公式文本处理、压缩和条件缓存。大模型档使用会话内逐条复评，本轮未调用智谱接口。
